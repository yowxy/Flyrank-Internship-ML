Work

1. Which page should an editor fix first?

Problem. 30,000 decaying pages, nobody can fix everything. The editor's question is order: which page first?

What I did. Framed it as ranked binary classification: predict a per-page decline flag, sort by predicted probability, judge on held-out clients. Bar set before training: AUC ≥ 0.70, P@200 ≥ 0.65.

Number. Frame + executed notebook; the bar is a promise, not a result yet. Label weak point written down: −20% is a human line, −19% vs −21% get different labels.

Where it breaks. No model trained at framing time; bar untested. See the notebook.

2. The hand rule that failed

Problem. If a one-line threshold orders the queue well enough, there is nothing for ML to beat. Test the rule first.

What I did. Scored the most generous hand rule (position > 20 and untouched 180+ days) as a queue on all 30,000 rows, same metric as the future model.

Number. Rule precision 0.538 ≈ the 0.542 base rate, recall 0.001 (14 of 16,262 declines). Model: RF 0.747 AUC / 0.68 P@50 vs rule 0.627 / 0.24 — the ~3x lift that earns ML its place.

Where it breaks. One rule tested, not the best possible rule; class medians overlap (declining vs healthy position 11.3 vs 10.0). See the notebook.

3. The label trap (in progress)

Problem. The decline label derives from trend_direction/trend_pct. Any feature list including them rereads the answer key.

What I did. Wrote the quarantine into the data contract first: label-derived columns and IDs are never features; client-holdout splits.

Number. Pending — leakage-demo notebook not yet executed. No caught-leak claimed until it runs.

Where it breaks. An unwritten demo proves nothing. See the contract.

    How this demo works, in plain words (no backend)

    A backend is the part of a site that lives on somebody else's computer: it remembers things (messages, emails) or runs things (a model) that a plain page cannot do alone. This demo has no backend — and needs none.

    What this feature does: it takes nine numbers you type, runs them through five yes/no rules, and shows which rules fired plus the action the rulebook suggests. That is the whole job.

    How the data flows: your numbers go from the form into a small function in this page, which checks each threshold and writes the answer back onto the page. Path: form → function → screen. Nothing is sent anywhere, nothing is stored, and it costs nothing to run — which is why it works the same on free hosting as anywhere else.
